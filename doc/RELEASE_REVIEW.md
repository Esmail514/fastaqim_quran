## النطاق

شملت المراجعة الكود العام والنواة وعرض حفص وورش والتفاعل والمتحكمات
والثيم والمساعدات ومزودي الصوت، والاختبارات والمثال، وبيانات المصادر
والرسوم والخطوط، وأدوات الاستيراد والتوليد، والتوثيق والتراخيص والتغليف.
حُفظت تعديلات المستخدم الموجودة سابقًا؛ لم تُعد كتابة الأصول القرآنية
أو الخطوط أو رسوم المصادر. النسخة التاريخية من النص في جذر الباكج باقية
محليًا، لكنها مستبعدة من النشر لوجود النسخة المطابقة داخل `lib/src/data/`.

## القرارات المعتمدة

- إبقاء ترخيص MIT مع حماية النص القرآني والاسم والنسخة الرسمية من الانتحال
  والتخريب؛ صلاحيات التعديل والتوزيع في MIT وCC BY 4.0 محفوظة.
- تخصيص النسخة الكاملة بأصولها للاستخدام غير التجاري والخيري، دون ادعاء
  تغيير تراخيص الكود الأصلي أو مواد الغير.
- إضافة سياسة عربية وإنجليزية وملف دعم، وإظهار وسائل التواصل في README
  وسياسة الأمان. لم تُرسل رسائل فعلية إلى هذه العناوين.
- تجهيز الإصدار `0.1.0` بوصفه أول إصدار لهذه الهوية؛ حُفظ سجل إصدارات
  qcf_quran الأصلية ونسب المؤلفين.
- إنشاء مستودع خاص حتى تُوثق صلاحية النشر العام للأصول.

## الفحوص التقنية

بيئة التنفيذ: Windows، **Flutter 3.41.9**، **Dart 3.11.5**.
يبقى الحد الأدنى المعلن Flutter 3.29 / Dart 3.7؛ لم يُشغَّل إصدار الحد
الأدنى أو جميع المنصات ضمن هذه المراجعة.

| الفحص | النتيجة |
| --- | --- |
| `flutter analyze --no-preamble` | دون أخطاء أو تحذيرات أو ملاحظات |
| `flutter test --no-pub --reporter expanded` | نجحت اختبارات الباكج الـ76 |
| الاختبار نفسه داخل `example/` | نجح اختبار فتح المثال |
| `flutter build web --no-pub --no-tree-shake-icons` داخل المثال | نجح بناء web وWasm dry run |
| SHA-256 للأصول المحددة في manifest حفص وورش | 612 بصمة مطابقة |
| مصدر حفص والملف المولّد | 6236 سجلًا، وتطابق التوليد بعد توحيد نهايات الأسطر |
| مصدر ورش وهندسة الصفحات | 6214 آية، 604 صفحات، 6218 منطقة؛ أربع آيات ممتدة بين صفحتين |
| `git diff --check` | بلا أخطاء مسافات |
| فحص pub التجريبي الأول | 55 MB مضغوط؛ كشف تنبيهات Git واسم مجلد التوثيق وتمت معالجتها |

نُقل مجلد التوثيق من `docs/` إلى `doc/` وفق تنبيه Pub، مع حفظ الملفات
وتحديث الروابط وأداة توليد HTML. `.pubignore` يحفظ استثناءات الأسرار
والبناء والكاش ويستبعد نسخة النص التاريخية المكررة في الجذر.
نتيجة فحص التغليف النهائية محفوظة محليًا في `build/publish-dry-run.log`؛
نجاحه التقني لا يمنح إذنًا لنشر الأصول.

## عوائق الحقوق قبل الإصدار العام

1. **خطوط صفحات QCF:** كل الخطوط الـ604 تحمل إشعارًا داخليًا يتطلب إذنًا
   مسبقًا للطباعة والنشر من مجمع الملك فهد؛ 183 منها تذكر دار المعرفة
   أيضًا. يوجد إشعار للاستخدام الخيري فقط وعدم البيع. هذه شروط موجودة في
   الملفات نفسها وليست مجرد استنتاج من README.
2. **بقية الأصول القديمة:** خط أسماء السور يذكر `qul.tarteel.ai` وIcoMoon
   بلا ترخيص داخلي مستقل؛ خط أرقام الآيات بلا شروط ترخيص واضحة. الخط
   `arsura.ttf` يذكر احتفاظ الحقوق، وهو غير مستخدم في pubspec الحالي.
   الصور الثلاث `mainframe.png` و`mainpagenum.png` و`mainpagenum_no.png`
   تحتاج أيضًا توثيق مصدر وصلاحية إعادة توزيع.
3. **الترخيص المختلط:** MIT للكود لا يغطي تلقائيًا هذه المواد؛ إذن المجمع
   لمصدره الأصلي لا يثبت وحده حق توزيع جميع تحويلات الخطوط وإضافات الغير.

خطوط `assets/fonts/` القديمة عددها 608، وحجمها 55,362,256 بايت. هي منفصلة
عن خطي حفص وورش Unicode الموثقين. لا يكفي حذف خطوط الصفحات من الأرشيف:
ذلك يكسر عرض حفص، ويحتاج تصميم إصدار بأصول بديلة وفحص عرض جديد.
لا تُحذف إشعارات الحقوق الداخلية من الملفات لتجاوز هذه المشكلة.

## حدود التحقق والمخاطر المتبقية

- تطابق البصمات والهيكل يثبت هوية المصدر والعدد والتغطية؛ لا يمثل مراجعة
  شرعية أو بصرية مستقلة لكل حرف وكل صفحة، أو استماعًا لكل تسجيل.
- حفص محلي، وكذلك نص ورش وخطه وهندسته. رسوم ورش المحلية ثلاث صفحات؛
  الصفحات 4–604 تعتمد افتراضيًا على الإنترنت أو builder يقدمه التطبيق.
- رسوم الشبكة مثبتة على commit مصدر، لكن العارض الافتراضي لا يقارن
  `svgSha256` وقت التشغيل. تُفحص هذه البصمات في الاستيراد والتحقق؛
  يلزم مصدر رسم مطابق لهندسة النقر عند تخصيص التحميل.
- إجمالي رسوم ورش لو أضيفت كلها 345,453,658 بايت؛ إدراجها كاملة في حزمة
  واحدة يزيد الحجم على التوصية الرسمية للحجم غير المضغوط.
- اختبارات الصوت تعتمد استجابات مضبوطة وحدود ترقيم موثقة. لم يُعد اختبار
  كل فهرس حي أو تحميل كل رابط صوتي؛ الخدمة وتوفر التسجيل مسؤولية مصدره.
- لم تُجر مراجعة مستقلة لجميع المنصات أو أجهزة حقيقية أو قارئات الشاشة.
  اختبار الحد الأدنى للـSDK خطوة مناسبة قبل توسيع ادعاء التوافق.
