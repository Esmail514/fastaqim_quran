# دمج حفص وورش في mushaf_riwayat

أضيف دعم الروايات إلى الباكج نفسه. تبقى حفص هي القيمة الافتراضية، وتبقى رموز عرضها وخطوط صفحاتها الأصلية وواجهات قراءتها السابقة متاحة. صُحح ربط النص المقروء لحفص بمصدره الأصلي كما هو موضح أدناه.

## متطلبات التطبيق

يتطلب الإصدار Flutter 3.29 أو أحدث. للوصول إلى رسوم الصفحات والتلاوات عبر الإنترنت، أضف صلاحية `android.permission.INTERNET` إلى ملف Android الرئيسي المستخدم في إصدار release، وفعّل `com.apple.security.network.client` في entitlements لتطبيق macOS. المثال المرفق يتضمن هذه الإعدادات.

## إصلاح النص المقروء لحفص

أظهر التحقق أن حقل `content` في الملف القديم يجمع نصوص ورش بالتسلسل مع ترقيم ورموز عرض حفص، بدل ربطها بمرجع السورة والآية. لذلك كان `getVerse(1, 1)` يعيد الحمد بينما رمز العرض يمثل البسملة، وكانت قيم النص في آخر ٢٢ سجلًا `null`. حقلا رموز العرض `qcfData` و`qcfv4data` وفهرسة صفحات حفص لم يكونا سبب هذا الخلل. حقل البحث `text_normal` كان مطابقًا للنص الإملائي لحفص في جميع السجلات الـ٦٢٣٦.

صُحح المصدر الذي تستخدمه واجهات `quranText` و`getVerseData` و`getVerse` والبحث: النص المقروء والنص الإملائي مأخوذان من حزمة حفص الأصلية للمجمع، ويربطان صراحة برقم السورة والآية. بقي الملف القديم محفوظًا للأرشفة دون تعديل، وبقيت رموز العرض وفهارس الصفحات كما هي. لا تستخدم الملف الداخلي القديم مباشرة للوصول إلى النص المقروء؛ استخدم واجهات الباكج العامة.

ملف المصدر الأصلي `assets/hafs/source/hafsData_v2-0.json` محفوظ دون تحرير أو تطبيع للحروف. ملف Dart المشتق منه يحفظ نص المصدر نفسه لتعمل الواجهات المتزامنة دون انتظار تحميل assets. `HafsText.getSourceVerse` يعيد نص المصدر مع رمز نهاية الآية الأصلي؛ يعيد `getVerse` النص دون هذا الرمز افتراضيًا، ويمكن طلب علامة النهاية بخياره السابق. الخط المقترن بالنص الأصلي هو `HafsText.fontFamily`، وهو مستقل عن خطوط رموز الصفحات QCF.

```dart
Text(
  HafsText.getSourceVerse(1, 1),
  textDirection: TextDirection.rtl,
  style: const TextStyle(
    fontFamily: HafsText.fontFamily,
    package: 'mushaf_riwayat',
  ),
);
```

القائمة العامة `quranText` تحتفظ بشكل السجلات السابق ذي الحقول الستة، وأصبحت `final` بقائمة وسجلات للقراءة فقط بدل تعريفها السابق `const`. إذا كان التطبيق يستخدمها داخل تعبير `const` فليحوّل ذلك الاستخدام إلى `final` أو قراءة وقت التشغيل.

## عرض المصحف والنقر

```dart
import 'package:mushaf_riwayat/mushaf_riwayat.dart';

PageviewQuran(
  riwayah: QuranRiwayah.warsh,
  initialPageNumber: 1,
  onTap: (surahNumber, verseNumber) {
    // الأرقام هنا تتبع ترقيم ورش المختار.
  },
  onAyahTap: (reference) {
    // مرجع يحمل الرواية أيضًا، لفتح تفسير أو طلب تلاوة.
  },
);
```

يمكن استخدام الخيارات نفسها مع `QcfPage(pageNumber: 1, ...)` لعرض صفحة واحدة. يظل استخدام `PageviewQuran()` دون تحديد الرواية عرضًا لحفص.

عرض ورش يستخدم رسوم الصفحات ومواضع الآيات من المصدر نفسه، مع حفظ توزيع الحروف والسطور دون إعادة لف النص حسب عرض الشاشة. تتغير أبعاد الرسم ومناطق النقر معًا؛ الأجزاء المتفرقة من آية واحدة تعيد المرجع نفسه، بما فيها استمرار الآية في الصفحة التالية. النقر والضغط المطول متاحان معًا في عرض حفص وورش، والمساحات الخالية خارج مناطق الآيات لا تعيد آية.

تتوافر هندسة النقر محليًا لكل الصفحات الـ٦٠٤. رسوم أول ثلاث صفحات مضمنة؛ بقية الرسوم تقرأ عبر الإنترنت من إصدار مثبت للمصدر. النص والخط محليان. لتوفير رسوم الصفحات محليًا استخدم `warshPagePictureBuilder` أو `WarshMushaf.fromData` مع رسوم وهندسة موثقة ومتطابقة. يجب أن يشغل الرسم الذي يعيده builder كامل المستطيل الذي يخصصه له الباكج، وأن يستخدم `page.viewBox` نفسه.

رسوم ورش ثابتة في توزيع الكلمات وعناصر الصفحة. تدعم إعدادات الخلفية والهوامش وتلوين الرسم كاملًا عبر `verseTextColor` وتحديد الآيات عبر `verseBackgroundColor`. خيارات إعادة تنسيق النص أو إخفاء عناصر المصدر أو `verseNumberBuilder` تخص عرض QCF؛ لتخصيص تفاصيل الرسم الثابت قدم رسمًا مطابقًا بواسطة builder. التطبيق مسؤول عن جاهزية هذا الرسم المخصص وتطابقه مع إحداثيات `viewBox`. يجب أن تكون صفحات `WarshMushaf.fromData` متفردة ومرقمة بالتتابع من ١ إلى آخر صفحة.

مصدر الرسوم يحافظ على أشكال حروف المصحف وتخطيط السطور، لكنه يزيل إطار الطبعة وبعض عناصر رأس الصفحة وأرقام الصفحات ويعيد رسم زخرفة علامة الآية. لذلك لا يوصف هذا العرض بأنه صورة مطابقة لجميع تفاصيل الصفحة المطبوعة. يمكن توفير صور الطبعة الأصلية مع هندسة متوافقة من خلال builder إذا كانت هذه المطابقة مطلوبة. لا تتفعّل مناطق النقر الافتراضية أثناء تحميل الرسم أو عند فشل تحميله.

عند تعذر جلب الرسم الافتراضي تظهر حالة خطأ مع زر لإعادة المحاولة؛ تبقى مناطق الآيات غير فعالة حتى ينجح التحميل.

واجهات البيانات السابقة، مثل `getVerse` و`getPageNumber` و`getVerseCount`، تحتفظ بمعنى حفص. استخدم مستودع ورش المستقل للاستعلام عن نصه وصفحاته:

```dart
final warsh = await WarshMushaf.load();
final ayah = warsh.getVerse(2, 285);
final pages = warsh.getPageNumbers(2, 285);
```

## مراجع الآيات

احفظ الرواية مع رقم السورة والآية في الإشارات المرجعية وطلبات الصوت والتفسير:

```dart
const reference = QuranAyahReference(
  riwayah: QuranRiwayah.warsh,
  surahNumber: 1,
  verseNumber: 1,
);
```

المرجع `warsh:1:1` يختلف عن `hafs:1:1`. لا تنقل تفسيرًا أو مقطعًا صوتيًا بينهما اعتمادًا على تطابق الرقم فقط. ورش في مصحف المدينة يستخدم العدّ المدني الأخير، وعدده ٦٢١٤ آية؛ حفص هنا يستخدم العدّ الكوفي، وعدده ٦٢٣٦. اختلاف العدد لا يعني نقص النص.

## التلاوات عبر الشبكة

مزودا MP3Quran وEveryAyah يعيدان بيانات وروابط للتطبيق. لا يجلبان أجسام ملفات الصوت ولا يضيفان ملفات MP3 إلى assets، ولا ينشئان مخزنًا صوتيًا على الجهاز. التطبيق يمرر الرابط إلى مشغله ويختار سياسة التخزين المناسبة.

MP3Quran يوفر روابط السور وقائمة السور المتاحة لكل مجموعة. مجموعة مكتملة تعني توافر السور الـ١١٤، ويمكن تشغيل روابطها بالتتابع. هوية الرواية والطريق تؤخذ من بيانات الخدمة؛ ورش العام، والأزرق، والأصبهاني مجموعات مختلفة في الفهرس.

```dart
final api = Mp3QuranApi();
try {
  final readers = await api.getReciters(riwayahId: 2);
  final complete = readers
      .expand((reader) => reader.moshafs)
      .where((collection) => collection.isComplete);
  if (complete.isNotEmpty) {
    final surahUrl = complete.first.surahUri(1);
    // مرر surahUrl إلى مشغل التطبيق.
  }
} finally {
  api.close();
}
```

`riwayahId: 2` يمثل ورش العام في MP3Quran، و`18` الأزرق، و`10` الأصبهاني. يمكن قراءة فهرس الروايات من `getRiwayat` بدل تثبيت أسماء العرض.

EveryAyah يوفر مقاطع مفهرسة لكل قارئ. لا تتطابق فهرسة ورش عند جميع القراء مع ترقيم المصحف المعروض. في فهرس عبد الباسط تختلف أعداد المقاطع في الشعراء والملك عن العدّ المدني الأخير؛ وفي الدوسري وياسين يتبع عدد المقاطع العدّ الكوفي. يلزم تحويل موثق عند هذه الاختلافات، وقد يحتاج تشغيل جزء من مقطع إلى توقيت موثق. لا يعيد الباكج ترقيم القرآن لتوافق خدمة الصوت.

```dart
final clips = EveryAyahProvider().resolveAyah(
  const QuranAyahReference(
    riwayah: QuranRiwayah.warsh,
    surahNumber: 2,
    verseNumber: 285,
  ),
  reciter: EveryAyahReciters.warshAbdulBasit,
);
final ayahUrl = clips.single.uri;
```

عند غياب تحويل موثق يرمي المزود `EveryAyahMappingRequiredException` بدل اختيار مقطع بالرقم نفسه. هذا ينطبق على الشعراء والملك عند عبد الباسط، وعلى التحويل من ترقيم المصحف إلى مقاطع الدوسري وياسين. يمكن أن يعيد التحويل الذي يقدمه التطبيق عدة مقاطع مع أوقات البداية والنهاية الموثقة. `clipUri` يبني رابطًا برقم **مقطع المصدر**؛ لا يستخدم باعتباره تحويلًا تلقائيًا لرقم الآية المعروضة. بناء الرابط لا يثبت مراجعة حدوده الصوتية بالاستماع.

## المصادر وحدود التحقق

- [مجمع الملك فهد — ورش](https://qurancomplex.gov.sa/warsh/): المرجع الأصلي للنص والخط والطبعة.
- [quran-meta](https://github.com/quran-center/quran-meta): مرجع لبيانات العدّ والتحويل بين المراجع.
- [typst-quran-package](https://github.com/NaifAlsultan/typst-quran-package): مرجع لرموز كلمات ورش وخطوطها.
- [Quran SVG](https://github.com/quran-ws/quran-svg): مصدر رسوم الصفحات ومناطق النقر، مثبت إلى إصدار محدد في `assets/warsh/manifest.json`.
- [توثيق MP3Quran](https://www.mp3quran.net/ar/api) و[فهرس EveryAyah لورش](https://everyayah.com/data/warsh/): مصادر التلاوات.

فُحصت تغطية مناطق النقر لكل الصفحات الـ٦٠٤ وجميع آيات ورش الـ٦٢١٤، بما فيها الاستمرار عبر الصفحات، ومطابقة صفحة كل منطقة لبيانات النص الأصلي. فُحص بقاء النص كما في المصدر وقراءة جميع مضلعات النقر. وقورنت جميع نصوص حفص الـ٦٢٣٦ ونصوص البحث والصفحات بمصدرها الأصلي، مع التحقق من بقاء رموز QCF دون تغيير. اختبارات التفاعل تشمل اختلاف حجم العرض والإحداثيات السالبة والمساحات الخالية وتبديل الرواية والنقر والضغط المطول معًا. اختُبر رسم أول ثلاث صفحات فعليًا في Flutter، وتنتج صور المعاينة في `build/warsh-page-1.png` إلى `build/warsh-page-3.png`.

نجاح هذه الفحوص لا يمثل مراجعة قرآنية مستقلة، ولا شهادة بمطابقة جميع الصفحات بصريًا أو جميع مقاطع الصوت مسموعًا. إشعارات النص والخطوط والبيانات مستقلة عن ترخيص كود الباكج، وتُحفظ مع الأصول المستخدمة.
